Magic Crystal はフレーム単位の挙動で成立するパズルゲームです。
開発時は [開発運用ルール](../specifications/development_rules.md) のゲームエンジン保護ルールを遵守し、キャラクターの移動・ジャンプ・落下・当たり判定・入力反映タイミングを変更しないでください。

## 要望・バグ指摘

### バグ修正
- [ ] 編集モードで、上キーと決定キーがコンフリクトしている
    - プレイ中の入力タイミングや物理挙動に影響しない範囲で修正する。

### アプリ機能
- [ ] マップ解放システム
    - 最初は10マップしか解放されていない
    - 10マップすべてクリアーすると次の10マップが解放される
    - 解放の状態は永続化されている
- [ ] 追加マップ機能
    - "EXTRA MAP" のようなメニューを追加する
    - その中に、編集可能なマップと読み込んだマップを表示する
    - 編集可能マップはシェアすることができる
    - ただし、そのマップをクリアーした記録がない場合はシェアできない
    - 読み込みマップは10個まで保存できる
    - 10個を超えると古いものから削除される
    - お気に入り設定をすると、削除されなくなる（最大5個）
    - 現行のEDITモードはモードとしては廃止し、編集可能マップの編集機能にする
    - マップには名前をつけることができる
    - マップには難易度をつけることができる
    - マップの難易度は★1～★5まで
    - 編集者が何ステージ解放できているかによって、星を付けられる範囲が変わる
        - 10ステージクリア: ★1のみ
        - 20ステージクリア: ★1〜★2
        - 30ステージクリア: ★1〜★3
        - 40ステージクリア: ★1〜★4
        - 50ステージクリア: ★1〜★5
    - 10ステージクリアしていない場合は "EXTRA MAP" は解放されない
    - 編集者が解放しているステージに応じて、編集起動で使用可能な地形が解放される
- [ ] シェア機能
    - X(Twitter)でマップをシェアできるようにする
    - マップタイトル、難易度、プレイ用のURLとマップの画像などをポストできる
- [ ] マップダウンロード機能
    - シェアされたマップを取り込む機能
    - 取り込んだらそのままプレイ画面に遷移する
    - 仕組みとしては、URLのqueryにbase64でエンコードされたタイトル、難易度、マップデータがあるイメージ

### 共通ライブラリ適用
- [ ] 保存データ管理を共通 DataManager に移行する
    - GameWorks OAK の `src/lib/core/dataManager.js` を相対 import して使用する
    - `new DataManager('magic-crystal')` によるゲームID名前空間保存へ移行する
    - 現在の `magic_crystal_settings` と `magic_crystal_level` の既存データ移行方針を決める
    - 設定、編集マップ、マップ解放状態、追加マップ、お気に入り、チュートリアル進行状態を同じ名前空間内で管理できるようにする
    - マイグレーションが必要な保存データは `getSavedData` / `setSavedData` と `migrationMap.init()` を使用する
    - 単純な一時設定や互換データは `getValue` / `setValue` の使用可否を検討する
    - 移行作業ではゲームエンジン部を変更しない
- [ ] ゲーム内テキストの i18n 対応方針を検討する
    - `project_info.json` は対応済み
    - ゲーム本体のメニュー、HOW TO PLAY、設定画面を多言語化するかを決める
    - 対応する場合は GameWorks OAK の `src/lib/core/i18n.js` を相対 import して使用する
    - 長文説明は `lang-store` とテンプレート描画 API の利用を検討する
