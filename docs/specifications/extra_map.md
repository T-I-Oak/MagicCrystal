# Extra Map Specification

## 概要

Extra Map は、通常マップとは別にユーザーが保持・編集・共有・読み込みできるマップ領域です。
URL からダウンロードしたマップも、ユーザーが作成したマップも、同じ保持マップとして扱います。
通常マップ 10 ステージをクリアすると、保持マップの編集機能が解放されます。
保持マップのプレイと共有 URL からの読み込みは、編集機能の解放条件を持ちません。

## 定数

以下の個数は実装上の定数として管理し、将来変更できるようにします。

- 保持マップ数: 50
- 編集機能解放条件: 通常マップ 10 ステージクリア

## EXTRA MAP メニュー

EXTRA MAP メニューは以下のどちらかを満たす場合に利用可能になります。

- 編集機能が解放済み
- 保持マップが 1 件以上存在する

どちらも満たさない場合、タイトルメニュー上では `???` のような未解放表示にします。
完全に非表示にはしません。

タイトル画面では、既存の `MAP EDITOR` メニューを `EXTRA MAP` メニューに置き換えます。
`???` 表示の場合もタイトルメニュー上の位置は維持します。
`???` 表示にカーソルを合わせることはできますが、決定操作を行っても EXTRA MAP 画面へは遷移しません。
このとき通知は表示しません。

EXTRA MAP 内では、カーソルで保持マップのスロットを選択し、スマート左 / 右で操作機能を選択します。
決定操作を行うと、選択中スロットに対して選択中の機能を実行します。

## EXTRA MAP 画面

EXTRA MAP 画面は、保持マップを扱うための一覧画面です。
通常ステージの Stage Select とは別の画面として実装します。
EXTRA MAP 画面からタイトル画面へ戻る操作は、キャンセルキー短押しとします。
画面上の戻るボタンは Soft Pad のキャンセルキーフェイスと `BACK` ラベルで表示し、長押し表記は使いません。

### 画面構成

EXTRA MAP 画面は、保持マップを 1 画面内にまとめて表示します。
通常ステージの Stage Select で 50 ステージを表示できているため、保持マップ 50 件はタブ分割しません。

タブ切り替え操作は持ちません。

### 共通レイアウト

マップはギャラリー形式のスロットとして表示します。
スロットには以下を表示します。

- ステージ識別子
- 難易度
- クリアーステータス
- お気に入りステータス
- ミニマップ

スロットのヘッダー行は、左側にステージ識別子、続けて難易度、右側にクリアーステータスとお気に入りステータスを表示します。
ミニマップはヘッダー行の下に表示します。
クリアーステータスやお気に入りステータスは、ミニマップを覆うラベルではなく小さな状態アイコンとして表示します。

カーソルは 1 画面内のスロット上を上下左右に移動します。
セクション境界をまたぐ移動も、見た目のグリッド配置に沿って自然に行います。
既存保持マップだけでなく、空スロットにもカーソルは移動できます。
空スロットでも、機能バーで選択中の機能を実行します。
編集機能が未解放の場合でも空スロットにカーソルは移動できますが、`CREATE` は無効状態になります。

### スロット順

保持マップは 50 個の固定スロットで管理します。
スロット位置はユーザー操作によって自動的に並べ替えません。
作成済み保持マップと空スロットは、それぞれの位置を維持します。
そのため、保持マップ一覧には空スロットがとびとびに存在する場合があります。

お気に入り設定は表示順には影響しません。

空スロットを表示する場合は `EMPTY` 表示とし、マップ内容は表示しません。
保持マップが 1 件も存在しない状態で EXTRA MAP 画面に入れるのは、編集機能が解放済みの場合のみです。
この場合は空スロットから新規保持マップを作成できます。

### 複数タブでの更新

複数ブラウザタブで同じ保存データを同時に編集するケースに対する排他制御は行いません。
保持マップに UID を持たせた競合解決や、保存時の世代チェックは行わず、最後に localStorage へ保存したタブの結果を有効とします。
そのため、別タブで先に保存された編集結果は、後から保存したタブの結果で上書きされる可能性があります。

### ステージ機能バー

EXTRA MAP 画面では、画面下部にステージ機能バーを表示します。
ステージ機能バーの左右には Soft Pad のスマート左 / 右キーフェイスを表示し、機能選択を切り替えられることを示します。
カーソルキーはスロット選択に使用し、スマート左 / 右は機能選択に使用します。
決定キーは、選択中スロットに対して選択中の機能を実行します。
EXTRA MAP 画面へ戻ったとき、機能選択は直前に選択していた機能を維持します。EXTRA MAP ではプレイ、編集、コピー、共有など利用目的が一定ではないため、画面表示のたびに特定の機能へ初期化しません。
スロットをマウスまたはタッチでクリックした場合、未選択スロットならそのスロットへカーソルを移動するだけとし、選択済みスロットなら選択中の機能を実行します。
機能バーの項目をマウスまたはタッチでクリックした場合、未選択機能ならその機能へカーソルを移動するだけとし、選択済み機能ならその機能を選択中スロットに対して実行します。

ステージ機能バーには以下を固定順で表示します。

- PLAY
- EDIT または CREATE
- COPY
- PASTE
- FAVORITE または UNFAVORITE
- SHARE

空スロットの場合、`EDIT` の位置は `CREATE` 表示に切り替えます。
それ以外の機能は位置を維持したまま無効状態として表示します。
保持マップの場合、`CREATE` の位置は `EDIT` 表示に切り替えます。
お気に入り状態の保持マップでは、`FAVORITE` の位置を `UNFAVORITE` 表示に切り替えます。

無効状態の機能が選択されている場合も、機能バー上の選択枠は表示します。
ただし、無効状態の機能には Soft Pad の決定キーフェイスを表示しません。
戻る操作は機能選択には含めず、Soft Pad のキャンセルキーフェイスと `BACK` ラベルを持つ独立したボタンとして表示します。
機能ボタンの幅は、現在の言語で表示されるラベル幅、左右余白、選択時に表示する Soft Pad の決定キーフェイス分を基準に算出します。
選択状態の変化でボタン幅が変わらないように、決定キーフェイス分はすべての機能ボタン幅にあらかじめ含めます。
`EDIT` / `CREATE` や `FAVORITE` / `UNFAVORITE` のように状態によってラベルが切り替わる機能は、現在の言語で取り得るラベル候補の最大幅を使ってボタン幅を固定します。

`EDIT` は編集機能が解放済みの場合のみ有効です。
編集機能が未解放の場合、`EDIT` は無効色で表示し、決定操作時には通常マップ 10 ステージクリアー後に利用可能になることを短い通知で知らせます。
`CREATE` は編集機能が解放済みの場合のみ有効です。
編集機能が未解放の場合、`CREATE` は無効色で表示し、決定操作時には通常マップ 10 ステージクリアー後に利用可能になることを短い通知で知らせます。
`CREATE` を実行した場合は、新規保持マップを作成し、そのままステージ編集画面へ遷移します。
`SHARE` はクリア済みの保持マップのみ有効です。
未クリアの保持マップでは、`SHARE` を無効色で表示し、決定操作時にはクリア済みでないためシェアできないことを短い通知で知らせます。
無効状態の `SHARE` は、シェア可能条件をユーザーに示すため非表示にはしません。
`PASTE` はコピー済みステージが存在する場合のみ有効です。
コピー済みステージが存在しない場合、`PASTE` は無効色で表示し、決定操作時には貼り付け元がないことを短い通知で知らせます。
無効状態の `PASTE` は、貼り付け可能条件をユーザーに示すため非表示にはしません。

## 保持マップ

保持マップは、ユーザーが EXTRA MAP 内に保持するマップです。
ユーザーが新規作成したマップと、共有 URL から読み込まれたマップは同じ保持マップとして扱います。
保持マップは最大 50 件です。

新規作成する保持マップは、左上にポータルを 1 つ配置し、それ以外は空き地の状態で作成します。
ステージにはポータルが 1 つ必要です。
ステージ編集では、2 個目のポータルを配置した場合に既存ポータルを消し、新しいポータルのみを残します。
ポータルの上に他の地形を配置することはできません。

保持マップの機能:
- プレイ
- ステージコピー
- ステージ編集
- ステージペースト
- マップシェア
- お気に入り設定
- マップ削除

保持マップのプロパティ:
- ステージ
- 難易度
- マップクリアーステータス
- お気に入りステータス

一覧表示では、各保持マップのクリアーステータスが分かる表示にします。
マップシェアは、その保持マップをプレイでクリアしたことがある場合のみ有効です。
ステージ編集またはステージペーストを行った場合、その保持マップのクリアーステータスは未クリアに戻します。
難易度のみを変更した場合、ステージ内容は変わらないためクリアーステータスは変更しません。
保持マップのリセット機能は持ちません。
ステージ編集では `SAVE` と `HOLD B DISCARD` を用意し、`SAVE` した場合のみ編集内容を保持マップへ反映して編集画面を終了します。
`HOLD B DISCARD` した場合は編集開始前のステージ内容と難易度を保持して編集画面を終了します。
`SAVE` によってステージ内容が変わった場合、クリアーステータスは未クリアに戻します。
SAVE 時に、ステージがパズルとしてクリア可能かどうかは検証しません。
クリア不可能なステージがシェアされることは、クリアーステータスによって防ぎます。

### ステージ編集画面

ステージ編集画面では、通常編集中はステージ編集操作を優先します。
編集開始時のカーソル初期位置はポータルのあるマスとします。ポータルが見つからない場合は左上 `(0, 0)` とします。

- 方向入力: 編集カーソル移動
- スマート左 / スマート右: 機能選択を切り替え
- 決定: 選択中の機能を実行
- キャンセル長押し: 編集内容を破棄して終了
- Keyboard のフルキー `0` から `7`: 対応する地形を選択し、現在のマスへ直接配置

ステージ編集画面では、マップ下部に機能バーを 1 行で表示します。
機能バーの左右には Soft Pad のスマート左 / 右キーフェイスを表示し、機能選択を切り替えられることを示します。
選択中の機能には選択枠、選択背景、Soft Pad の決定キーフェイスを表示します。
地形選択中は、機能バー上では現在選択中の地形を 1 つの代表枠として表示します。
スマートキーで地形 `0..7` の範囲を移動している間、代表枠の位置は変えず、表示する地形アイコン・番号・名称だけを更新します。
画面上部の地形一覧にも、現在選択中の地形の枠を表示します。
機能ボタンの幅は、現在の言語で表示されるラベル幅、左右余白、選択時に表示する Soft Pad の決定キーフェイス分を基準に算出します。
地形機能は地形アイコン分も幅に含め、8 種類の地形名候補の最大幅を使って固定します。
これにより、地形選択の変更や選択状態の変化で機能バーのボタン幅が変わらないようにします。

```text
↖ [A HELP] [地形アイコン N: 地形名] [DIFFICULTY] [SAVE] ↗ [HOLD B DISCARD]
```

機能選択順:

- `HELP`
- 地形 `0..7`
- `DIFFICULTY`
- `SAVE`

マウスまたはタッチで操作する場合、機能バーとマップ座標は以下のルールで扱います。

- 未選択の機能をタップした場合は、その機能を選択するだけで実行しません。
- 選択済みの機能をタップした場合は、その機能を実行します。
- 未選択のマップ座標をタップした場合は、編集カーソルをその座標へ移動するだけで、選択中の機能は実行しません。
- 選択済みのマップ座標をタップした場合、選択中の機能が地形 `0..7` のときだけ、現在選択中の地形をその座標に配置します。
- 選択済みのマップ座標をタップした場合でも、選択中の機能が `HELP` / `DIFFICULTY` / `SAVE` のときは、その機能を実行しません。
- 画面上部の地形一覧をタップした場合は、地形を選択するだけで配置は行いません。

ステージ編集画面に入った直後の初期選択は `HELP` とします。
`HELP` はステージ編集画面の操作方法モーダルを表示します。
操作方法モーダルでは、最初に「編集カーソルを動かす」「機能を選ぶ」「地形を配置する」「保存または破棄して終了する」という基本フローを説明します。
その後、Soft Pad のキーフェイスを代表表示として、Edit Mode 固有の操作を説明します。
各操作キーが Keyboard / Numpad / Gamepad のどれに対応するかは、HOW TO PLAY の操作キー対応表を参照します。
Keyboard のフルキー `0` から `7` で地形選択と直接配置を同時に行えることも表示します。
操作方法モーダルの内容はスクロール可能とします。
操作方法モーダルは、キャンセルキー、またはマウス/タッチクリックで閉じ、ステージ編集画面へ戻ります。
`DIFFICULTY` は難易度設定モーダルを表示します。
難易度設定モーダルは設定系モーダルとして扱い、通常の設定画面と共通の枠、タイトル、項目名、選択マーカー、値変更 UI、`B CLOSE` 表示を使用します。
タイトルは `DIFFICULTY SETTINGS`、設定項目名は `DIFFICULTY` とします。
難易度設定モーダルは、タイトル、難易度の設定項目、選択中の難易度説明、`B CLOSE` で構成します。
値行には設定中の難易度を Soft Pad 代表表示の星で表示します。
値行にカーソルがある状態で、左右操作により難易度を変更します。
難易度変更は通常の設定画面と同じく即時に編集セッションへ反映し、難易度説明も現在の難易度に合わせて切り替えます。
`B CLOSE` またはキャンセルキーは難易度を元に戻さず、モーダルだけを閉じます。
設定可能な最高難易度を超える値には変更できません。
`SAVE` は編集内容と難易度を保存して EXTRA MAP 画面へ戻ります。
`HOLD B DISCARD` は編集内容を破棄し、編集開始前のステージ内容と難易度を保持して EXTRA MAP 画面へ戻ります。
`CREATE` 直後の初回編集で `HOLD B DISCARD` した場合は、作成した保持マップ自体を破棄し、元の空スロット状態に戻します。

お気に入り設定できる保持マップ数に上限はありません。
お気に入り設定は、対象保持マップを一覧上で見分けやすくするための状態です。
お気に入り設定された保持マップは誤削除を避けるため、`DELETE` を無効表示します。

`DELETE` は対象スロットを消去する機能です。
実行時は確認モーダルを表示し、削除確定で保持マップを空スロットへ戻します。
キャンセルした場合は保持マップを変更せず EXTRA MAP 画面へ戻ります。
共有 URL からの読み込み時に空スロットがない場合の通知モーダルには、削除操作は含めません。

共有 URL から読み込まれたマップも、通常の保持マップと同じく編集・再シェアできます。
元作者のマップを改変して再シェアすることは許容します。
24 x 13 の小さなマップでは厳密なコピー防止は困難であり、またプレイヤーがそのマップをクリアーできない限りシェアできないため、編集・再シェアを制限しません。

## 難易度

通常マップと保持マップには難易度を設定できます。
難易度は 1 から 5 までの 5 段階です。
UI 上では数値ではなく星の数で表します。

初版では通常マップ 50 ステージの難易度をすべて 1 とします。
通常マップの難易度は Stage Select のヘッダー行に表示します。

編集者が通常マップを何ステージ解放しているかによって、設定可能な最高難易度が変わります。

- 通常マップ 10 ステージクリア: `★` まで
- 通常マップ 20 ステージクリア: `★★` まで
- 通常マップ 30 ステージクリア: `★★★` まで
- 通常マップ 40 ステージクリア: `★★★★` まで
- 通常マップ 50 ステージクリア: `★★★★★` まで

保持マップの新規作成時のデフォルト難易度は、その時点で編集者が設定可能な最高難易度です。
難易度未設定の保持マップは作りません。
共有 URL には難易度を 1 文字で含めます。
共有 URL から読み込んだ保持マップの難易度は共有 URL から復元します。

編集機能が解放されている場合でも、編集者が設定可能な最高難易度を超える難易度は設定できません。
共有 URL から読み込んだ保持マップの難易度が設定可能な最高難易度を超えている場合、読み込み時点では共有 URL の難易度を保持します。
その保持マップを編集した段階で、難易度を編集者が設定可能な最高難易度に調整します。

## ステージ編集で使用可能な地形

ステージ編集では、編集機能が解放された時点で 8 種類すべての地形を使用できます。
地形は 8 種類のみであり、分割解放すると編集でできることが少なくなりすぎます。
また、高難度のマップが必ずしも特別な地形を使うとは限らないため、地形の分割解放は行いません。
ステージ編集画面に表示する地形名は、HOW TO PLAY の terrain 章で使用している名称と一致させます。
地形名は i18n 対応し、HOW TO PLAY と同じ翻訳リソースを参照します。
「空き地」は HOW TO PLAY の terrain 章には表示されない追加地形として、同じ terrain 名称グループ内に定義します。

## マップ共通機能

### クリアーステータス表示

通常マップ、保持マップは、一覧上でクリアーステータスが分かる表示にします。
保持マップでは、クリアーステータスはマップシェア可能かどうかを判断するための重要な情報です。
クリアーステータスはミニマップを覆うラベルではなく、一覧アイテムのヘッダー行に小さな状態アイコンとして表示します。
ヘッダー行は、将来の難易度表示やお気に入り表示を含められるように、左側にステージ、続けて難易度、右側にクリアーステータスとお気に入りステータスを置く構成を想定します。
通常マップの Stage Select では、過去クリアー済みかどうかを状態アイコンで表示します。
今回のゲームでクリアー済みになり選択できないステージは、マップ内容を表示せず完了状態として表示します。

### プレイ

対象マップを通常プレイと同じゲームエンジンでプレイします。
キャラクターの移動・ジャンプ・落下・当たり判定・入力反映タイミングは変更しません。

### ステージコピー

保持マップからステージコピーできます。
コピーしたステージの貼り付け先は保持マップのみです。
ステージコピーでは、ステージデータと難易度をコピーします。
コピー元の難易度が、貼り付け先の編集者が通常設定できる最高難易度を超えている場合、ペースト時の難易度は設定可能な最高難易度に丸めます。
ステージペーストを行った保持マップのクリアーステータスは未クリアに戻します。

## 通常マップ

通常マップはステージコピー元として利用しません。
通常マップ自体のステージ編集・ステージペーストは行えません。
通常マップには難易度を付与します。
初版ではすべての通常マップを難易度 1 とします。

## 難易度定義

難易度の定義は別途定めます。
難易度定義は、編集者が保持マップの難易度を選択するときの指針として表示します。
通常マップの難易度設定にも同じ定義を適用します。
現在の ★1 から ★5 の説明文は初期案であり、リリース前にプロジェクトオーナーのレビューを受けます。

## 共有 URL 読み込み

保持マップの作成者は、クリア済みの保持マップを共有できます。
共有 URL をクリックしたユーザー側では、URL に含まれるマップ情報を保持マップとして保存します。

共有マップ情報は URL の `map` query parameter に保持します。

```text
https://t-i-oak.github.io/MagicCrystal/?map=A3...
```

ゲーム起動時に URL の `map` query parameter へ共有マップ情報が含まれている場合、以下の順に処理します。

- `map` query parameter から共有マップ情報を取得する
- 共有マップ情報をデコードし、ステージデータへ展開する
- デコード結果のサイズ、地形値、形式識別子を検証する
- 不正な共有マップ情報の場合は保持マップへ保存せず、読み込み失敗モーダルを表示する
- 読み込み失敗モーダルの OK または CLOSE 操作後、タイトル画面に戻る
- 正常な共有マップ情報の場合は、先頭側の空スロットへ保持マップとして保存する
- 空スロットがない場合は EXTRA MAP 画面へ遷移し、空きがないためダウンロードできなかったことをモーダルで知らせる
- 保存または重複解決の完了後、その保持マップのプレイを開始する
- 共有マップ情報の処理後は、`history.replaceState` などでブラウザの URL から `map` query parameter を削除する

保持マップの読み込みとプレイは条件なしで利用できます。
編集機能が未解放でも、共有 URL から読み込まれたマップは保存・プレイできます。
処理済みの `map` query parameter を削除することで、リロード時に同じ共有マップが再処理されることを防ぎます。

共有 URL から展開したステージデータが既存の保持マップと同一の場合は、新規追加しません。
重複判定では難易度を比較せず、ステージデータのみを比較します。
既存の保持マップが見つかった場合は、その保持マップの難易度を変更せず、そのマップのプレイを開始します。
同一ステージデータを持つ保持マップが複数存在する場合は、先頭側の保持マップをプレイ対象にします。

## 共有マップデータ形式

共有 URL に含めるデータは、ステージデータ、形式識別子、難易度です。
マップタイトル、ユーザーコメントは共有 URL に含めません。
共有する人がタイトルやコメントを書きたい場合は、X などの投稿本文に記載します。

共有マップデータは、URL-safe な 64 文字集合を使います。

```text
ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_
```

地形は 8 種類固定です。
HOW TO PLAY の terrain 章に記載される 7 種類の地形に「空き地」を加えた 8 種類を、共有マップエンコード上の `0..7` として扱います。
地形種類を増やす予定はありません。
公開後に互換性へ影響する変更が必要になった場合は、既存形式を変更せず新しい形式識別子を追加します。
初版リリース前のため、現時点では B format の仕様変更を許容します。

共有マップデータの先頭 1 文字は形式識別子です。
形式識別子の次の 1 文字は難易度です。

```text
A = v1 fixed
B = v1 RLE
C = v1 RLE-2
D = v1 dictionary
```

難易度は URL-safe な 64 文字集合のうち、`1..5` を表す 1 文字で保持します。
難易度の表示形式は、UI 上および共有画像上では `★` から `★★★★★` までの星の数で表します。
保持マップには必ず難易度を設定します。
新規作成時はデフォルト難易度を持たせ、共有 URL 生成時に難易度が欠落する状態を作りません。

### v1 fixed

v1 fixed は 2 マスを 1 文字で表します。

```text
index = firstTile * 8 + secondTile
char = alphabet[index]
```

13 x 24 の固定サイズでは、ステージ本体は 156 文字です。
形式識別子と難易度を含めると、共有マップデータは 158 文字です。

### v1 RLE

v1 RLE は、同じ地形の連続を 1 文字で表します。
1 文字は地形種類と連続数の組み合わせです。

```text
index = tile + (runLength - 1) * 8
char = alphabet[index]
```

連続数は `1..8` です。
9 マス以上連続する場合は、8 マス単位で複数ランに分割します。

デコード時は逆変換します。

```text
tile = index % 8
runLength = floor(index / 8) + 1
```

v1 RLE の展開結果は 13 x 24 の 312 マスに一致する必要があります。
312 マスより少ない、または多いデータは不正な共有マップ情報として扱います。

### v1 RLE-2

v1 RLE-2 は、同じ地形の短い連続を 1 文字、長い連続を 2 文字で表します。
長い連続を 8 マスごとに分割しないことで、空き地や地面などが広く連続するマップの共有 URL を短くします。

短距離 RLE は、連続数 `1..4` を 1 文字で表します。

```text
index = tile + (runLength - 1) * 8
char = alphabet[index]
```

このとき `index` は `0..31` です。
デコード時は逆変換します。

```text
tile = index % 8
runLength = floor(index / 8) + 1
```

長距離 RLE は、連続数 `5..256` を 2 文字で表します。

```text
firstIndex = tile + 32 + ((runLength - 1) % 4) * 8
secondIndex = floor((runLength - 1) / 4)
firstChar = alphabet[firstIndex]
secondChar = alphabet[secondIndex]
```

このとき `firstIndex` は `32..63`、`secondIndex` は `1..63` です。
デコード時は逆変換します。

```text
marker = firstIndex - 32
tile = marker % 8
remainder = floor(marker / 8)
runLength = secondIndex * 4 + remainder + 1
```

257 マス以上連続する場合は、連続数 `5..256` の範囲に収まるように複数の RLE-2 文字列へ分割します。

v1 RLE-2 の展開結果は 13 x 24 の 312 マスに一致する必要があります。
312 マスより少ない、または多いデータは不正な共有マップ情報として扱います。

### v1 dictionary

v1 dictionary は、v1 RLE-2 に短い汎用地形パターンの辞書参照を加えた形式です。
辞書は、通常ステージ前半を参考に、ステージ固有の長い並びではなく複数ステージで自然に現れる汎用パターンとして手動定義します。

辞書参照は 1 文字で表します。

```text
index = 56 + dictionaryIndex
char = alphabet[index]
```

辞書は以下の 8 パターン固定です。

| dictionaryIndex | pattern | tile sequence |
| ---: | --- | --- |
| 0 | `S.S` | `1,0,1` |
| 1 | `S..S` | `1,0,0,1` |
| 2 | `S...S` | `1,0,0,0,1` |
| 3 | `.SS.` | `0,1,1,0` |
| 4 | `.SSS.` | `0,1,1,1,0` |
| 5 | `.r.` | `0,4,0` |
| 6 | `.R.` | `0,2,0` |
| 7 | `.RR.` | `0,2,2,0` |

表中の記号は、`.` が空き地、`S` が土、`R` が岩、`r` が回帰の紅晶を表します。

v1 dictionary の短距離 RLE は、v1 RLE-2 と同じく連続数 `1..4` を 1 文字で表します。

```text
index = tile + (runLength - 1) * 8
char = alphabet[index]
```

長距離 RLE は、辞書参照と衝突しないように `32..55` を使い、連続数 `5..196` を 2 文字で表します。

```text
runValue = runLength - 5
firstIndex = tile + 32 + (runValue % 3) * 8
secondIndex = floor(runValue / 3)
firstChar = alphabet[firstIndex]
secondChar = alphabet[secondIndex]
```

このとき `firstIndex` は `32..55`、`secondIndex` は `0..63` です。
197 マス以上連続する場合は、連続数 `5..196` の範囲に収まるように複数の長距離 RLE 文字列へ分割します。

デコード時は以下のように扱います。

- `index` が `0..31` の場合は短距離 RLE として展開する
- `index` が `32..55` の場合は次の 1 文字と合わせて長距離 RLE として展開する
- `index` が `56..63` の場合は辞書参照として展開する

v1 dictionary の展開結果は 13 x 24 の 312 マスに一致する必要があります。
312 マスより少ない、または多いデータは不正な共有マップ情報として扱います。

### 形式選択

共有 URL を生成するときは、v1 fixed、v1 RLE、v1 RLE-2、v1 dictionary を生成し、最も短い形式を使用します。
同じ長さの場合は、実装で定めた安定した優先順に従います。
RLE 系はマップによって fixed より短くなる一方で、短い連続が多いマップでは fixed より長くなることがあります。
そのため、特定形式のみを採用せず、生成時に短い形式を選択します。

## シェア仕様

シェア対象は、クリア済みの保持マップです。
保持マップを編集またはステージペーストした後は、再度プレイでクリアするまでシェアできません。

シェア時には以下を用意します。

- 共有マップデータを query string に含めたゲーム URL
- 対象マップのプレビュー画像
- ゲームタイトル
- GameWorks OAK 系のハッシュタグ

X などに投稿する本文には、ゲームタイトル、共有 URL、ハッシュタグを含めます。
共有本文は以下の形式です。

```text
【MAGIC CRYSTAL】
自作ステージに挑戦してみて！
<共有 URL>
#MagicCrystal #GameWorksOAK
```

英語表示時は 2 行目を `Play my custom stage!` にします。
マップタイトルは共有 URL に含めず、投稿本文にもアプリ側から固定挿入しません。

共有画像は対象マップを視認できる PNG として生成します。
共有画像には以下を表示します。

- `Magic Crystal`
- 難易度
- マッププレビュー
- `© T.I.OAK 2026 | GameWorks OAK`

共有処理は端末種別で分岐します。
PC では共有画像のみをクリップボードへコピーし、コピー完了後に X 投稿確認 UI を表示します。
ユーザーが確認 UI の `OPEN X` を選択した場合、投稿本文を X intent 側へ渡します。
モバイルでは Web Share API を使い、共有画像と共有本文を OS の共有シートへ渡します。
具体的な共有処理は BurstCascade / GravityFreight の既存処理を参考にします。

## 保存データ

Extra Map 関連の保存データは、共通 DataManager の `magic-crystal` 名前空間内で管理します。

保存対象:
- 保持マップ一覧
- 保持マップの難易度
- 保持マップのクリアーステータス
- 保持マップのお気に入りステータス
- EXTRA MAP メニュー解放判定に必要な通常マップクリア状況

保持マップ一覧を localStorage / GameDataStore に保存する場合、ステージと難易度は共有マップ形式の `mapData` 文字列として保持します。
実行時は `mapData` を展開し、ステージと難易度を通常の保持マップデータとして扱います。
クリアーステータスとお気に入りステータスは `mapData` には含めず、保存データ上のメタデータとして保持します。

## 実装上の注意

Extra Map 実装では、ゲームエンジン部を変更しません。
既存のキャラクター挙動はパズル成立条件であるため、移動・ジャンプ・落下・当たり判定・入力反映タイミングを変更しないでください。
