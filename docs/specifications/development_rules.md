# Magic Crystal 開発運用ルール

本プロジェクトを健全に維持・開発するためのエンジニア向けルールです。

## 1. バージョン管理

### 1.1 バージョン表記
アプリのバージョンは、セマンティックバージョニング（Major.Minor.Patch）に準拠して管理します。
- 現在のバージョンは `package.json` に定義され、Vite の `__APP_VERSION__` を通じて `src/Game.js` に注入されます。
- バージョン情報は、タイトル画面の左下にも表示されます。

### 1.2 バージョン更新ルール
機能追加、バグ修正、またはリソースの変更を行った際は、必ずバージョン番号を更新してください。
- 小規模な修正: パッチバージョンを上げる（例: 1.0.0 -> 1.0.1）
- 新機能の追加: マイナーバージョンを上げる（例: 1.0.1 -> 1.1.0）

## 2. ゲームエンジン保護ルール

Magic Crystal はフレーム単位の挙動によって成立するパズルゲームです。
キャラクターの移動、ジャンプ、落下、当たり判定、硬直、入力反映タイミングなどのゲームエンジン部は、既存ステージの解法と難易度に直結するため、原則として変更してはいけません。

### 2.1 変更禁止対象
- `Physics.js` に含まれる移動・衝突判定ロジック。
- `Game.js` のプレイヤー状態更新、ステージクリア、ミス、待機フレーム、ジャンプ状態に関わる処理。
- `Input.js` のうち、プレイ中の移動・ジャンプ・穴掘り・向き反転の入力タイミングに影響する処理。
- `Level.js` のうち、プレイヤー移動可否やタイル変化タイミングに影響する処理。

### 2.2 変更可能対象
以下は、ゲームエンジン部と分離している場合に限り変更可能です。

- メニュー、設定画面、ステージ選択、追加マップ一覧などの UI。
- 保存形式、DataManager への移行、公開メタデータ。
- エディタ専用 UI。ただしプレイ中の入力や物理挙動に影響させないこと。
- 描画表現。ただし当たり判定やフレーム進行を変更しないこと。

### 2.3 例外
ゲームエンジン部を変更する必要がある場合は、実装前にオーナー承認を必須とします。
承認を得た場合でも、既存ステージの解法が維持されることを検証するテストまたは確認手順を用意してください。

## 3. ビルドキャッシュ対応

ブラウザキャッシュによる古いスクリプトの実行を防ぐため、Vite のビルド成果物はハッシュ付きファイル名で出力します。
`index.html` では `src/main.js` を module script として読み込み、公開時は Vite が生成する `dist/` 内のハッシュ付き JS を使用します。

### 3.1 実装方法
`index.html` では以下の入口を指定します。

```html
<script type="module" src="src/main.js"></script>
```

### 3.2 更新手順
ソースコードを変更する場合は、共通 workflow に従って `package.json` のバージョンを更新してください。
手動で script URL にクエリパラメータを付与する運用は行いません。

## 4. 著作権表記
- タイトル画面下部に適切な著作権および制作年を表示します。
- 描画ロジックは `src/Renderer.js` の `drawTitleMain` メソッドで管理します。
